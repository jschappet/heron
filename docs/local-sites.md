# Local multi-site development

Run Heron from its repository with `cargo run`. With the existing port 8582:

| Site | Address | Build directory | API identity (`hosts.host_name`) |
| --- | --- | --- | --- |
| Regen Skagit | http://regen.localhost:8582 | `../regen-skagit/dist` | `regenerateskagit.org` |
| ReVillage Society | http://revillage.localhost:8582 | `../revillage-society/dist` | `revillagesociety.org` |
| Workshop | http://workshop.localhost:8582 | `../workshop.schappet.com/dist` | `workshop.schappet.com` |

The mappings live in `config/development.toml`. Paths are relative to Heron's
working directory. Change the port in these URLs if `web_config.port` differs.
Restart Heron after changing the configuration.

Each hostname selects both the site's static directory and its database identity.
Frontend requests keep using `/api/`; they stay on the site's own origin.
Cookies and browser storage are separate for each hostname. This does not create
separate databases or change the authorization rules of existing API endpoints.

Build each site once with `npm run build` in its repository. While editing, run
`npx @11ty/eleventy --watch` in each active site's repository. This rebuilds the
static files without starting extra web servers; Heron serves the results.
Regen and ReVillage compile Tailwind during those builds. Rebuild ReVillage's
Pagefind search index with `npm run build` when testing search changes.

Modern browsers normally resolve `*.localhost` to loopback. If your local resolver
does not, add these names to your hosts file:

```text
127.0.0.1 regen.localhost revillage.localhost workshop.localhost
::1       regen.localhost revillage.localhost workshop.localhost
```

For a resolver-independent HTTP check:

```bash
curl --resolve regen.localhost:8582:127.0.0.1 http://regen.localhost:8582/
```

## Site identities

`api_host` must match an existing `hosts.host_name` exactly. Local aliases preserve
that identity's ID, roles, slug, and canonical base URL. They do not rewrite email
links or other canonical URLs generated by existing backend code.
A configured alias with a missing database identity returns a service-unavailable
error instead of silently using the Unknown identity.

Workshop has been added to the current local database. For another development
database that does not have it, add it once:

```sql
INSERT INTO hosts (slug, host_name, display_name, base_url, active)
SELECT 'workshop', 'workshop.schappet.com', 'Workshop',
       'https://workshop.schappet.com', 1
WHERE NOT EXISTS (
  SELECT 1 FROM hosts WHERE host_name = 'workshop.schappet.com'
);
```

## Compatibility

Mappings are enabled only in debug builds with `environment = "development"`.
`RUN_MODE` defaults to `development`, which loads `config/development.toml` over
`config/application.toml`. Production and staging do not use these aliases.

The old `localhost`/`webroot` workflow remains available. Each mapped site serves
its own `404.html`, or a plain 404 if it has none. Requests under `/api` never
fall through to static files. The mapping uses the same `X-Forwarded-Host`/`Host`
precedence as Heron's existing host middleware.
